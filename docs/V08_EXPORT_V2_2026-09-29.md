## Changes and compatibility

`export_bundle(store, format="v1")` preserves the default v1 body and serialization; `format="v2"` adds a completeness envelope and uses `etps-offline-export-v2`. The CLI exposes `export DB --output FILE --format v1|v2`, defaulting to v1. Other formats fail. V2 reads database heads, journals and report in one SQLite snapshot, without migrating the schema or committing a caller's transaction.

The envelope stores plan-order `slot_order`, per-slot `heads` with count/hash/state, and SHA-256 of the canonical encoding of `[plan_sha256, slot_order, heads]`. Replay verifies that digest, exact slot membership/order, journal lengths, final hashes (including empty seeds), and lifecycle states. Failures raise `InvalidRecord`; CLI errors remain concise and exit 2. Replay adds `export_completeness_bound` (true for verified v2, false for v1), without any new v1 warning.

| `export_erased_attempt` scenario | Before / default v1 | Opt-in v2 |
| --- | --- | --- |
| A completed journal is replaced with `[]`, leaving other evidence intact | Accepted as unattempted; `attempted=0`, warnings unchanged; completeness field is now false | Rejected with `export journal head count integrity failure` |
| Journals, heads and envelope are coherently rewritten together | Editable evidence remains replaceable | Accepted when internally consistent; completeness bound does not establish authenticity |

A coherent full rewrite defeats these checks. They detect accidents and truncation, not signing, attestation or actual execution. Global cross-slot chronology remains deferred: no global sequence exists in the current schema. Failed, running, aborted and unattempted slots remain visible.
